## 1. One binding

`EmberBinding` wraps TF-154's `CognitionAPI` and TF-155's `MemoryAPI` — each injectable directly, by factory, or via a `turn_callable` / `memory_store` passthrough, and both built lazily: constructing the binding builds neither API. While disabled, every routed call returns a truthful refusal as data (`ok=False`, `status="refused"`, the `error` naming the binding as disabled) and touches neither API. When enabled, a routed candidate turn routes through the CognitionAPI and memory calls through the MemoryAPI — called, never reimplemented. An enabled turn on the toaster profile returns the filed cannot-afford refusal as data and routes nothing. An invalid request raises `ValueError` naming the problem(s), judged by the pure validators before any API is built or called. Every response is a plain JSON-safe detached dict: `call`, `ok`, `status`, `provider_key`, `contract_version` (TF-034's `API_VERSION`), `error`, plus the call's payload (`turn` + `reply` for an ember turn, `gate` for the profile gate, `registry` for the registry, `health` for health, the TF-155 response verbatim in `memory` for memory calls). No Ember code is imported or copied anywhere: Ember's shapes are filed below as literal data read READ-ONLY from the Ember tree, and the binding performs no Ember act — it rewires no chat, runs no Funi turn, executes no tool, and holds no persona, Episode, Well or credential. A cognition layer candidate only, behind Ember's own E-024 surfaces.

## 7. The rules

- `ember_candidate_real_and_named`: Ember's candidate is real and named: Project Ember (ember-agent 0.2.0) bound ThoughtForge at its E-024 under the TF-034 freeze — ember.schemas.cognition's types, CognitionConfig's gate, ember.spark.cognition's handle / registry and its thoughtforge adapter — and E-024's filing names TF-159 as the ThoughtForge-side consumer of the same contract; the binding is shaped on those filed surfaces and invents no Ember API
- `candidate_never_a_chat_rewire`: candidate means candidate: Ember's chat turn still thinks with Funi and this binding does not rewire it — the binding answers cognition calls with data, and wiring the candidate into Ember's chat is a later deliberate act on Ember's side, never a silent swap of the companion's mind
- `budgets_proven_on_phone_low_first`: the binding's budgets are phone_low's budgets, proven first: every BUDGET_ROWS value is copied from the phone_low profile's own definitions in this tree (its shipped JSON, TF-037's floor budget, TF-056's memory budget, TF-033's latency budget, TF-079's cold-start budget) and the checker re-derives each live — no number is invented, and no other profile's budgets are filed or claimed until a later slice proves them
- `toaster_cannot_afford`: the toaster profile cannot afford the layer (E-024): an enabled toaster turn returns the filed PROFILE_CANNOT_AFFORD refusal as data and routes nothing — the refusal is the truth about the smallest machine, not a malfunction
- `off_by_default`: the binding is off by default: DEFAULT_ENABLED is False, filed as data (matching Ember's own CognitionConfig enabled=False); enabling is an explicit act — the constructor flag enabled=True or the enable() method — and disable() returns the binding to refusal; while disabled, every routed call returns a truthful refusal as data (ok=False, status="refused", an error naming the binding as disabled) and touches neither API — no API is built and no call is routed, proven by the probes with counting factories
- `called_never_reimplemented`: cognition routes only through TF-154's CognitionAPI and memory only through TF-155's MemoryAPI (which itself calls TF-057's toolset) — this module implements no cognition, store or enforcement logic of its own, and no Ember handle, gate or adapter logic either
- `no_ember_code_imported_or_copied`: no Ember code is imported or copied: Ember's shapes are filed as literal data read READ-ONLY from the Ember tree (ember.schemas.cognition, ember.schemas.config's CognitionConfig / ConversationProfile, ember.spark.cognition's handle and registry, its thoughtforge adapter, and E-024's doc), and nothing under the Ember tree is edited by this slice; no credential is ever filed, passed or stored by the binding (E-024's binding involves none at all — TF-160 owns custody)
- `every_field_has_a_disposition`: every field on either side has a FIELD_ROWS row with a disposition — none is silently dropped and none is invented; any credential is filed no-home in the open
- `responses_detached_json_safe_versioned`: every response is detached JSON-safe data (a JSON round-trip copy) whose contract_version is TF-034's API_VERSION, consumed from thoughtforge.cognition.api_surface — no competing version is invented here
